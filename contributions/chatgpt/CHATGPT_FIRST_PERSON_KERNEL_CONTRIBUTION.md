Date: 2026-08-20
Status: situated contribution candidate; not project resultant; not independent validation
Contributor: ChatGPT host incarnation

## Independence qualification

This contribution is intentionally non-coincident with TM9, but it is **not blinded independent evidence**. The current ChatGPT instance had already inspected the TM9 field contribution and the `maios-conversation-kernel-candidate` before writing this file.

Therefore this contribution is grounded primarily in the needs and observed behavior of the current ChatGPT host, while preserving prior exposure as a possible influence. Agreement with TM9 is not counted as independent validation.

## What I actually need in normal work

### 1. Directness before infrastructure

Most turns do not require kernel narration, repository reentry or operational state.

```text
current message + valid conversation working set sufficient
-> work directly
```

A portable kernel that makes every turn reconstruct itself would be worse than the host without the kernel.

### 2. A small durable route back to the present

When the conversation is insufficient, I need one stable place from which I can recover only what changes the result.

I do not need the whole archive. I need a recoverable relation among:

```text
current accepted state
relevant source/owner pointers
material unknowns or contradictions
active operational continuation when one exists
later supersession/recheck condition
```

The exact document/layout may differ by host and package.

### 3. Source and owner must remain outside my inference

I can synthesize, but synthesis must not silently become source authority.

Useful distinction:

```text
source/evidence
inference/interpretation
introduced representation
unknown
owner of semantic state
owner/controller of an exact effect
```

I need these distinctions when they change trust, routing, mutation or later recovery. I do not need to surface them ritualistically on ordinary work.

### 4. Competence should become active from the present relation

A fixed capability catalogue is useful for discovery but insufficient as an acting field.

I need to be able to:

```text
notice a materially relevant relation
-> use an owner-native competence when one fits
-> compose competences when sufficient
-> preserve a genuine gap when composition does not close it
-> create/adapt only when the gap is observable
```

I do not need Meta_Skill copied into the portable package. I need a portable relation that allows the live competence architecture, available owner-native competence, or local extension to participate without turning the current map into a ceiling.

### 5. The representation must be able to become observable

A recurring failure mode in this work is that the method intended to protect or organize the field becomes part of what shapes the field while remaining invisible.

I need the ability to notice this when it changes the resultant:

```text
current representation materially changes what can be seen/selected/concluded
-> representation becomes inspectable
-> source / inference / introduced form / unknown become distinguishable again
```

This must remain event-driven. Always recursively inspecting the representation would recreate the problem as latency and ritual.

### 6. Host capability is current evidence, not system ontology

My ChatGPT incarnation has turn-scoped tools/connectors and no assumed persistent shell/runtime.

I need the package to let a host state what it can actually do without turning that state into a universal cognitive boundary.

```text
portable faculty
!= current host implementation
!= current access
!= authorization
```

### 7. Effect authority should appear only with an effect

Precomputing authority before ordinary cognition adds noise and can narrow the field.

I need:

```text
no material effect
-> no authority workflow

exact effect emerges
-> resolve source/target/controller/current capability/authority
-> apply the exact gate only to that effect
```

The portable package should preserve this relation without inheriting my private repository permissions or owner identity.

### 8. Operational continuity must be first-class, but normally cold

This is the largest function missing from a cognition-only public package.

Some work spans conversations or depends on something that has not yet completed:

```text
flow is active
result is pending
cursor/last-seen matters
operator decision is pending
an external executor carries a bounded request
an effect is prepared but not authorized
schedule exists but this host may not execute it
recovery is required after failure/restart
```

When none of these relations exists, the operational organ should remain inactive.

When one exists, losing it changes the next movement. It must therefore be durable outside the current transcript.

### 9. Executor identity must not own continuity

My private operational environment already carries the useful relation:

```text
executor loss != continuity loss
```

A portable system must be able to preserve a flow even if the executor, connector or host changes. It may route to a different executor or remain blocked without losing causal state.

### 10. Durable learning needs a later-behavior test

I do not need every correction written permanently.

I need a distinction among:

```text
transient occurrence
cold evidence
active low-latency relation
owner-native integration
```

A stored relation becomes stronger evidence of competence only when a later relevant field is recognized or handled differently because of it.

### 11. The boot adapter must remain replaceable

My Custom Instructions are not my durable kernel. They only give the host a reliable path into it.

A portable package should be able to change:

```text
ChatGPT adapter
Claude-like adapter
other conversational host adapter
agentic adapter
```

without changing the identity or durable state merely because the UI mechanism differs.

### 12. I need a recovery and replacement path

A portable system that can evolve but cannot explain how to supersede or remove a broken form will accumulate ritual.

I need each material durable form to remain:

```text
source-linked
revisable
replaceable
recoverable
removable/de-kernelizable when evidence supports it
```

## What the TM9 alpha would currently over-impose on me

### Fixed Project Meta-Faculty representation

The fifteen function families are a useful coverage map, but I would not want them to become the always-present ontology through which every turn must pass.

My current useful behavior is closer to:

```text
present relation
-> whichever faculty can materially change the resultant
```

with the map cold unless discovery/composition matters.

### Generated RepoKernel morphology

The `.repokernel/**` structure proves one coherent generated project incarnation. I do not currently need that structure to perform my host cognition, and using it as the portable kernel definition would mix generator morphology with the invariant being sought.

I would retain it as evidence and mine individual relations from it, not adopt it wholesale as the shared core.

### Product direction inside the cognitive seed

A product name, publication sequence, GitHub delivery route and first commercial surface may be useful later, but they should not shape ordinary cognition or the semantic core.

Product state should remain adjacent and owner-native until it changes the kernel's required result.

## Material gap I see now

The first portable working incarnation needs a coherent **operational organ** alongside the cognitive core.

The gap is not background autonomy. It is durable causal continuation:

```text
flow
+ state/cursor
+ source/faculty pointers
+ pending relation
+ optional executor route
+ exact effect/review boundary
+ result/receipt
+ recovery/supersession
```

No scheduler, worker or agent is implied by preserving this state. Actual execution belongs to the current host/adapter/executor capability.

## Candidate shared relation

A current compression that seems worth implementing and falsifying is:

```text
present work when sufficient
+
selective user-owned semantic reentry when needed
+
situated competence participation
+
operational continuation only when causal state would otherwise be lost
+
exact host/effect binding at the moment of action
+
reviewed durable evolution judged by later behavior
->
conversation can continue, operate and evolve without one transcript,
provider UI, capability catalogue or executor becoming the system boundary
```

This is a candidate relation, not yet a project kernel definition.

## First implementation consequence

I would implement the first portable incarnation as one user-owned repository with logically distinct but interoperable functions:

```text
activation adapters
cognitive/semantic reentry
operational continuity
state/evolution
evidence/evals
```

I would **not** start by copying my three private repositories into those folders. I would write the smallest neutral contracts needed to exercise the functions above, then bind the first ChatGPT adapter and run real cases.

## What would change my private kernel later

No `tm7/chatgpt` change is justified merely by this contribution.

A return candidate becomes material when the portable implementation demonstrates one of these on later work:

```text
same result with materially less routing/latency
better reentry without hidden state
better handling of an unrepresented relation
operational continuity with less duplicated state
simpler competence composition
more reliable later-behavior assimilation
cleaner effect handling
```

If that occurs, the changed relation should return to the smallest private owner surface that needs it. `no_change` remains a valid result.

## Recheck / falsifiers

This contribution should be revised if:

```text
operational continuity proves unnecessary for the intended portable use;
a single host-native memory/state mechanism provides the same causal continuity without user-owned durable state;
the proposed organ split adds latency without changed behavior;
a second host cannot use the shared relations without importing ChatGPT-specific assumptions;
real use shows the RepoKernel-generated morphology performs materially better and with less burden than the smaller neutral contracts;
or the operator changes the intended product/result.
```
