## Useful outcome

A person or team owns a durable conversational kernel that can recover the
right context, distinguish source from inference, compose or create faculties,
attest real host capabilities and preserve reviewed evolution across chats and
tools.

## Delivery

```text
fork or generated repository
-> select and configure a host adapter
-> confirm installation separately
-> run ordinary work and bounded evals
-> preserve accepted state and capability receipts
-> evolve from source-bound behavioral evidence
```

## Current proof

- Linked RepoKernel input bundle validated.
- Deterministic L2 Project Kernel generated.
- Open-world Project Meta-Faculty and Problem/Possibility Seed present.
- ChatGPT adapter, capability field, evals and validator implemented locally.

## Proof still required

- Public remote creation and clean readback.
- Independent fresh-reader reconstruction.
- Real adapter installation outside the source environment.
- Positive and negative behavioral receipts.
- Neutral install/configuration experience for a second user.

## Expansion horizon

The current forms—repository, ChatGPT adapter, generated setup, public demo,
workbench and managed continuity—are possible incarnations, not the final
product ladder or a limit on what can emerge. New hosts, faculties, interfaces
and service relations remain owner-native and source-bound.

## MAIOS public relation

The MAIOS site may expose identity, purpose, current maturity, inspectable
outputs, GitHub proof, adapter installation and authority boundaries. It must
not claim activation, universal compatibility or OpenAI endorsement. Footer
visibility may begin under projects/tools; a primary Products navigation item
should follow a repeatable delivery contract rather than create one by naming.
