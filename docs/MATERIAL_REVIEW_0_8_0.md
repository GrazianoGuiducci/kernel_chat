## Scope

This review asks whether the consequence-aware FDLA resultant can coherently
become the next source/release identity. It evaluates the semantic owner,
condition-to-owner discovery, public capability truth, consumer proof,
compatibility and release/version boundaries.

It does not establish host behavior or longitudinal assimilation.

## Resultant

The target already owned the supporting relations in Core, Competence and
Evolution: temporal validity, current-vs-historical distinction, changed-field
readback, consequence learning, first-losing-transformation diagnosis and
semantic continuity.

The material delta is concentrated in FDLA itself and its consumers:

```text
in-flow FDLA remains

-> preserve event
-> preserve understanding actually available then
-> distinguish current understanding
-> recompose the present without retroactive narration or historical freezing
```

AGENTS makes that condition discover the FDLA owner. The structural validator
and an independent CommonMark consumer test prove the new route/anchor relation.
README and Architecture describe the broadened current capability.

Historical v0.7.0 release notes and review evidence remain unchanged.

## Compatibility

No deliberate incompatible contract change is introduced:

- portable entry remains 3.0.0;
- instance schema remains kernel_chat.instance.v1;
- configurator and ChatGPT adapter mechanics are unchanged;
- state and operations schemas are unchanged;
- configured bridges and installed host instructions do not require replacement
  merely because the deep kernel source changed;
- existing in-flow FDLA behavior remains valid.

## Version decision

`0.8.0` is selected.

A patch release would understate a new constitutive capability and its public
discovery/consumer contract. A pre-1.0 minor release preserves compatibility
while making the semantic expansion explicit.

`1.0.0` is not selected: this movement does not establish a new stable-contract
or maturity boundary.

## Release boundary

The promotion commit may update VERSION, CURRENT_STATE, CHANGELOG, this material
review and release notes. That exact resulting identity must receive its own
green CI before tag/release publication.

Tag/release publication, user-instance migration, configured adapter refresh
and installed host instruction updates remain separate effects.

## Review result

No material source blocker remains for a 0.8.0 promotion candidate.
