## Purpose

The plugin is an installable receiver projection of kernel_chat.

It does not copy the whole historical kernel into prompt context.

It packages the smallest workflows that let a receiving ChatGPT/Codex instance
reconstruct and exercise:

- present-first reentry;
- source authority;
- competence routing;
- learning return;
- exact-effect boundaries;
- receiver-relative continuation.

## First private plugin skills

~~~text
maios-present-first-reentry
maios-source-authority
maios-competence-routing
maios-learning-return
maios-effect-boundary
~~~

These operate with the host's actually available capabilities.

No GitHub/VPS capability is claimed merely from skill installation.

## Bridge phase

The next plugin phase should connect to MAIOS Bridge MCP.

Candidate user journeys:

1. Continue this project from the current source.
2. Read the repository state and tell me where we really are.
3. Use what this project learned last time.
4. Update the project kernel after this correction.
5. Check the VPS state and reconcile it with the repository.
6. Execute this bounded maintenance/deploy movement and give me the receipt.

GitHub and VPS are tool/authentication problems; the plugin skill remains the
workflow/meaning layer.

## Public boundary

The plugin must not imply:
- persistent subjective agent identity;
- background autonomy when the host does not provide it;
- access to GitHub/VPS unless the user connects the required bridge;
- authority to mutate a source merely because it can read it.

The source product remains GrazianoGuiducci/kernel_chat.
