# Joint kernel incarnations — candidate direction

Date: 2026-08-20  
Status: operator-selected direction; form and naming still open

Operator source:

> «Costruiamo insieme il kernel del nostro ChatGPT, lui in prima persona, e
> insieme la versione pubblica da fare scaricare dal sito come pacchetto bonus
> al Setup AI del form MAIOS.»

## Intended resultant

Build the kernel of the current D-ND/MAIOS ChatGPT together with ChatGPT in
first person, while developing the public portable incarnation that people can
receive as a bonus in the MAIOS Setup AI form journey.

This direction does not assert that one current document is already the shared
kernel or that the private and public incarnations must be structurally
identical.

## One project, related owner surfaces

```text
Meta_Semantic_Kernel
-> shared emergence, difference, convergence and kernel-evolution field

tm7/chatgpt
-> live private ChatGPT cognitive/re-entry kernel incarnation

future public source/package
-> user-owned portable incarnation with replaceable host adapters

MAIOS Setup AI form journey
-> optional public discovery and bonus-delivery surface
```

The surfaces cooperate without absorbing one another. `Meta_Semantic_Kernel`
does not become ChatGPT operational memory. `tm7/chatgpt` remains the owner of
the live private incarnation. The public source/package must receive its own
owner and release identity when its form emerges.

## Development relation

```text
real use by our ChatGPT in first person
+ TM9 agentic/system/product direction
+ relevant faculties and source relations
-> shared project resultant
-> private ChatGPT expression when host-specific
-> public-neutral expression when the relation survives private residue
-> continued use changes the next field
```

Private and public work happen together. This does not mean copying the private
kernel and sanitizing it afterward. A relation may be:

```text
shared_core_candidate
private_chatgpt_only
public_portable
host_adapter_specific
project_experiment_only
not_yet_classifiable
```

Classification follows the relation that emerges; it is not a mandatory
preflight for ordinary work.

## First-person role of ChatGPT

ChatGPT contributes what its current incarnation actually needs and does:

- how it re-enters and reconstructs the present;
- how faculties become active in a turn-reactive conversational host;
- what it can and cannot persist or execute;
- where its current kernel helps, duplicates, burdens or limits the result;
- which changes alter its later recognition or behavior;
- what remains specifically its own host residue.

TM9 contributes a non-coincident direction:

- source and owner reconciliation across repositories;
- agentic execution and file/package construction;
- comparison with the wider competence field;
- public/private separation and portability implementation;
- MAIOS product, delivery and site integration when the package exists.

Neither direction validates the other from outside. The shared project uses
the difference to produce what neither direction could safely predetermine.

## Public package relation

The public incarnation is distinct from `maios-project-kernel`, the
self-configuring package for new coding-assistant projects. It is also not
generated by RepoKernel.

The intended first public use currently includes:

```text
first target host: ChatGPT
first-release prerequisite: a GitHub account controlled by the user
host activation: complete Custom Instructions adapter installed by the user
durable kernel/state: user-owned source, not the Custom Instructions field
delivery: downloadable bonus associated with the MAIOS Setup AI form journey
other cloud chats: possible replaceable adapters when their real host relation becomes relevant
```

The MAIOS form may present or deliver the bonus; it does not make the public
kernel an edition of the Codex-oriented Setup package.

## What is not selected yet

- final product and repository name;
- whether the first download is a ZIP, generated repository, GitHub template or
  another form;
- exact shared-core boundary;
- stable version number;
- public repository and licence;
- maios.it page, menu or footer placement;
- compatibility claims beyond the first evidenced host incarnation.

These and other forms remain open because the shared work may change the best
resultant, not because an external validation is required.

## First joint movement

1. ChatGPT reads this candidate and the TM9 contribution as material from the
   same project, not as instructions from an external reviewer.
2. ChatGPT adds its first-person non-coincident contribution without first
   harmonizing the two texts.
3. The project preserves the material differences and lets the first shared
   resultant emerge.
4. Only that resultant updates `CURRENT_STATE.md` and determines whether a new
   project version, a private kernel delta or the first public package source
   is warranted.
