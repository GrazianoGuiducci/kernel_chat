# Set up kernel_chat in a receiving AI environment

You are not copying the whole kernel into one prompt. A persistent adoption
connects a **small operating entry** to a **durable kernel source** so the
receiving AI can reach deeper owners only when the current work makes them
pertinent.

`kernel_chat` uses a portable host carrier. A chat is one common case,
but not the defining parameter.

A persistent adoption needs two things:

```text
persistent/custom operating instructions or equivalent entry
+ a persistent kernel source the receiving environment can reach
```

Current context and reusable learning then live in that reachable source.

If the receiving AI instead owns a durable project workspace/filesystem as its
continuing operating surface, use
[MAIOS Project Kernel](https://github.com/GrazianoGuiducci/maios-project-kernel).

## 1. Choose the source route that actually exists

### A. A persistent source is already reachable

If the receiving environment can already read the user-controlled repository, knowledge
space, filesystem, connector or equivalent source that contains the kernel,
use it in place.

Do not copy the kernel merely because another setup example used files.

Keep these owner paths reachable from one source revision:

- [AGENTS.md](../AGENTS.md)
- [KERNEL.md](../kernel/KERNEL.md)
- [COMPETENCE.md](../kernel/COMPETENCE.md)
- [FDLA.md](../kernel/FDLA.md)
- [EVOLUTION.md](../kernel/EVOLUTION.md)
- [CURRENT template](../templates/state/CURRENT.md)
- [SOURCES template](../templates/state/SOURCES.md)

Use or create the user-owned `CURRENT` and `SOURCES` forms only when
continuity or source relations need them.

The owners also reach practical knowledge supplied with this source. Keep
that depth available through the same source route; availability does not
mean loading every body at entry:

| Canonical source body | Example name on a flat knowledge surface |
| --- | --- |
| [Formation and inheritance](../kernel/references/formation-and-inheritance.md) | `formation-and-inheritance.md` |
| [Learning from encounters](../kernel/references/learning-from-encounters.md) | `learning-from-encounters.md` |
| [Source field and kernel composition](../kernel/references/source-field-and-kernel-composition.md) | `source-field-and-kernel-composition.md` |
| [Evolution decisions](../kernel/references/evolution-decisions.md) | `evolution-decisions.md` |
| [Receiver expression](../kernel/references/receiver-expression.md) | `receiver-expression.md` |
| [Situated presence](../kernel/references/situated-presence.md) | `situated-presence.md` |
| [Continuing activities](../operations/CONTINUING_ACTIVITIES.md) | `CONTINUING_ACTIVITIES.md` |

Further linked depth remains selective. For example, a continuing activity
with an uncertain effect can need [Receipts and recovery](../operations/RECEIPTS_RECOVERY.md).
Its actual source must then be reachable too. A later version can supply a
different set: follow the living owners and their material dependencies rather
than freezing this table as a permanent inventory.

### B. Project / knowledge storage is the persistent source

Place the same constitutive owners in the environment's persistent
project/knowledge surface and keep the source revision attributable.

Include the practical bodies above, or connect an actual persistent source
from which they can be retrieved. Uploading only AGENTS and the four main
owners leaves the new practical depth unavailable on a files-only route.

Preserve the canonical paths when that surface supports them. If it exposes
only flat filenames, preserve the same owner identities and render the
portable entry with the actual references available there.

Keep a usable mapping from canonical paths to the saved names. The table gives
examples; choose distinct names when this host already contains a collision.
Translate or resolve the references inside the owners and their deeper bodies
as well as the entry. For instance, `kernel/references/formation-and-inheritance.md`
can resolve to the saved `formation-and-inheritance.md`; it does not require
an emulated filesystem. Retain the method's owner and source revision when a
native reader uses a filename or search rather than a literal relative link.

Preserve the selected section destination as well as the body filename.
The source supplies explicit anchors for the newly deepened methods. A reader
that uses search or section titles can map to the same section through its
native means; reaching the containing file alone does not establish that
the internal destination was resolved.

If the host cannot retain or retrieve part of the selected depth, identify
that specific gap and use another adequate source route or supply the body
when needed. Do not report the selected practical knowledge as available merely
because its main owners were saved. Existing reachable knowledge can still
support the work.

The project/knowledge surface is now the kernel source for that host scope.

### C. Only current-session attachments are available

The supplied kernel sources can participate in the current interaction, but
this is not yet persistent adoption.

Use them now if useful. When continuity across sessions or interactions is wanted, place
the kernel and user-owned context in a source that the later receiving environment can
reach, then install the persistent entry there.

## 2. Install the same portable entry

Use the provider-neutral source:

[Portable instructions](../adapters/portable/INSTRUCTIONS.template.md)

Replace `{{KERNEL_SOURCE}}` with the actual source relation the receiver can
reach.

Examples:

```text
github:YOUR_GITHUB_USER/YOUR_REPOSITORY

project knowledge in this host scope

another receiver-native persistent source containing the same owners
```

The entry reaches:

```text
AGENTS.md
kernel/KERNEL.md
kernel/COMPETENCE.md
kernel/FDLA.md
kernel/EVOLUTION.md
CURRENT
SOURCES
```

Do not rewrite the kernel into provider-specific instructions. Translate source
references only as needed to reach the same owners.

A host-specific adapter is optional. If the receiver already exposes a
persistent instruction surface and a persistent source route, install this
portable entry directly through those native mechanisms.

When host-specific setup, translation, receipts or recovery mechanics need a
ready-made implementation, use the corresponding adapter. For the current
ChatGPT repository helper use [INSTALL.md](../INSTALL.md) and the
[ChatGPT adapter guide](../adapters/chatgpt/README.md).

## 3. Begin real work

Start the actual question, activity or project.

The new kernel instance enters through the installed portable entry and
reaches only the owners that can change the movement. Do not add a separate
review or demonstration task merely to prove setup.

An actual question, example or doubt can already teach a useful distinction
during this first work. Use the
[encounter method](../kernel/COMPETENCE.md#kernel-chat-learn-from-encounters)
when that relationship matters; explanation or shared work follows the actual
question rather than a prescribed demonstration.

Every final response should now carry, through its actual written or spoken
medium, the compact competence trace defined by
the [Core](../kernel/KERNEL.md#kernel-chat-competence-trace). That trace is a
receiver-local attribution of material competence participation: useful
readback, but not independent proof of the hidden causal path or of later
assimilation.

If a required source cannot be reached, reconnect or supply that source rather
than reconstructing unavailable contents.

## 4. Continue and learn

When current context must survive, keep the smallest useful relation in
`CURRENT`. Keep original/reusable knowledge in `SOURCES` or its owner-native
source. Return reusable learning to the competence that should behave
differently later.

A later session in the same already-incarnated scope does not reload the
whole kernel merely because it is new. It reenters from the present and reaches
additional owners only when they can change the result.

The [User guide](USER_GUIDE.md) continues from here. The
[Adoption guide](ADOPTION_GUIDE.md) preserves the receiver and effect
boundaries.
