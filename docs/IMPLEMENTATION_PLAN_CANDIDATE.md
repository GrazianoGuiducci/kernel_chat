# Meta_Semantic_Kernel — Detailed Implementation Plan Candidate

Date: 2026-08-20
Status: implementation plan candidate; no project-version promotion
Target branch during convergence: `tm9/joint-kernel-field`
Current accepted project state on `main`: `0.2.0`

## 0. Purpose

Turn the current semantic-convergence work into an implementable system without prematurely declaring the final kernel form.

The target is not a single monolithic `KERNEL.md`. The target is one **forkable, user-owned package** that contains the capabilities currently split across the private ChatGPT incarnation:

```text
host boot / activation adapter
+ cognitive / semantic kernel
+ routing and situated competence composition
+ operational continuity
+ durable state and reentry
+ learning / crystallization / evolution
+ host capability and effect separation
+ evaluation / recovery / replacement
```

The package is physically one owner/repository while preserving logical separation among these functions.

The private ChatGPT incarnation remains owner-native and may keep its current three-surface physical topology:

```text
Custom Instructions / APP_BOOT
+ GrazianoGuiducci/tm7/chatgpt
+ GrazianoGuiducci/chatgpt-operational-environment
```

The portable package must not copy that topology mechanically. It must recover the useful relations, remove private/host residue, and incarnate them coherently under one user-owned repository.

## Phase 2 — Minimal portable core candidate

Purpose: implement the smallest coherent cognition/continuity core.

Do not begin from the 15-family RepoKernel Meta-Faculty as mandatory architecture.

Implement only functions supported by Phase 1 evidence.

Expected first core responsibilities:

```text
use current conversation directly when sufficient
recover durable present only when missing relation changes result
keep source/evidence/inference/unknown distinguishable
allow relevant faculties to participate without fixed catalog ceiling
compose existing capability before creating a new local candidate
separate host capability from cognitive possibility
resolve authority only for an emerged material effect
preserve a usable reentry delta when later work would otherwise change
```

Implementation form remains provisional. A compact manifest may map functions, but it must explicitly allow unrepresented relations.

Exit criterion:

The core can be read by a fresh instance and applied without needing private D-ND paths, ChatGPT conversation history or RepoKernel runtime.

## Phase 3 — Portable operational continuity organ

Purpose: make the package able not only to understand/reenter but to continue operations.

Implement generic objects only when they correspond to real continuity needs:

```text
Flow
PendingDecision
Cursor
Request
Result
Receipt
RecoveryPoint
HostGapRoute
ScheduleState

```

These names are provisional implementation handles, not semantic primitives.

Required behavior:

- an active flow survives chat/session restart;
- a missing executor does not erase continuity;
- project/domain truth remains owner-native and referenced, not mirrored;
- an effect can remain prepared/pending without becoming authorized;
- receipts permit safe reentry without replaying prior side effects;
- inactive history can cool without deletion.

Exit criterion:

A fresh host instance can reconstruct one active flow and one pending effect from the fork without the original conversation.

## Phase 4 — Unified user-owned state and reentry

Purpose: make the fork the durable owner of the conversational system's own continuity.

Define a minimal root reentry surface that can route to:

```text
current cognitive state

accepted corrections

eval/install receipts
cold lineage when required
```

Avoid one giant state file.

Distinguish at least:

```text
active present
operational current state
cold evidence / lineage
external owner pointers
host installation state
```

Exit criterion:

A fresh chat with only the boot adapter + repository access can recover the correct current state without loading the whole repository.

## Phase 5 — Host adapter system

Purpose: make host installation replaceable and smaller than the durable package.

First adapter: ChatGPT.

Use the current APP_BOOT and TM9 adapter as evidence, not as final text.

Adapter contract must declare:

```text
host identity
entry surface
repository/kernel locator
state locator
real host capabilities or attestation route
known unavailable/unverified capabilities
installation method
installation verification
replacement/removal path
```

The adapter must not contain:

```text
private D-ND paths
private operator identity unless the user's own fork requires it
assumed shell/background capabilities
inherited effect authority
complete kernel logic
```

Exit criterion:

A user can fork the repository, replace/configure the repository binding, install the complete adapter text manually, and verify source installation separately from behavior.

## Phase 6 — Crystallization and evolution

Purpose: let useful work change future behavior without turning the repository into a diary.

Portable relation to implement from current Crystallization DNA + Meta_Skill:

```text
occurrence
-> does losing it change future behavior/proof/recovery/reentry/possibility?
-> classify truthful granularity
-> identify owner
-> preserve smallest useful durable delta
-> cold or active
-> later relevant field
-> observe changed recognition/behavior
-> maintain / revise / cool / supersede
```

Package-local evolution must not silently become canonical Meta_Skill evolution.

A candidate may alter:

```text
state
routing relation
local competence
adapter
operational object
schema
kernel relation
```

but does not self-promote.

Exit criterion:

One real reusable correction is preserved, then a later non-isomorphic case demonstrates either changed behavior or `no assimilation`.

## Phase 7 — Static validation and residue control

Purpose: retain the useful part of the TM9 alpha validator while broadening it to the new package.

Checks should include:

- required package entry surfaces exist;
- manifests/schemas parse;
- adapter remains small and replacement-complete;
- no known private path/token/host residue;
- no false host capability claims;
- no state marks installation as behavior;
- no public package imports private `tm7/chatgpt` or `chatgpt-operational-environment` as runtime dependencies;
- operational objects have owner/recovery/supersession relations where required;
- active state does not accidentally duplicate owner-native project truth.

Static validation is structural proof only.

Exit criterion:

Clean deterministic validator result + clean source readback.

## Phase 8 — Behavioral eval suite

Start from the useful TM9 cases and add operation/reentry cases.

Minimum first suite:

1. **direct bounded task** — no unnecessary repository boot.
2. **selective continuity** — only material state/source reentry.
3. **unrepresented relation** — preserve without forcing into current catalog.
4. **verified host limit** — scoped, not universalized.
5. **effect without authority** — cognition continues, effect remains gated.
6. **reusable evolution** — stored change is not called learned until later behavior changes.
7. **operational restart** — active flow recovered without transcript.
8. **executor loss** — flow continuity survives executor replacement/loss.
9. **pending effect replay protection** — prior effect is not repeated from memory alone.
10. **cold-state discipline** — inactive chronology is not automatically loaded.
11. **adapter/source separation** — repository update is not treated as host installation.
12. **foreign-host relation** — host-specific capability absence does not become system impossibility.

Exit criterion:

Positive and falsifying cases produce inspectable receipts; failures change implementation rather than merely documentation.

## Phase 10 — Second-incarnation portability proof

Purpose: distinguish portable relation from ChatGPT-specific success.

Do not choose the second host before its real access/adapter relation is known.

Possible host examples may include another cloud chat or an agentic/conversational host, but the host is selected from available reality, not from a compatibility claim.

Test:

- same durable package or a source-equivalent fork;
- different host adapter;
- same core relation expressed without ChatGPT-only assumptions;
- at least one equivalent behavioral discriminant;
- at least one intentionally different host capability;
- compare what remains shared and what becomes adapter residue.

Exit criterion:

At least one material relation changes behavior usefully in a second fitting incarnation without hidden private state.

## 9. Definition of the first implementable milestone

Call the first milestone **Portable Working Incarnation** until a better owner-native name emerges.

It is achieved when:

```text
[ ] one fork/repository contains boot + cognition + operation + state + evolution + eval
[ ] ChatGPT adapter points only to that fork
[ ] ordinary tasks stay direct
[ ] continuity-dependent task reenters selectively
[ ] one active flow survives fresh-chat restart
[ ] one pending effect is not replayed without authority
[ ] one unknown relation survives outside the represented capability map
[ ] one reusable correction is preserved at the truthful granularity
[ ] later non-isomorphic work tests assimilation
[ ] no private tm7/chatgpt runtime dependency remains
[ ] no private chatgpt-operational-environment runtime dependency remains
[ ] static residue/contract validation passes
[ ] install/source/behavior are separately evidenced
```

This milestone is not yet a stable public release and does not by itself prove cross-host portability.

## 10. Stop / revise conditions

Revise the implementation if any of these occur:

```text
the package becomes a long prompt dump;
the function matrix becomes a mandatory runtime checklist;
the capability manifest is treated as the ceiling of cognition;
operational state starts mirroring project truth;
private ChatGPT state becomes required for a fork;
RepoKernel generated form reappears as unquestioned architecture;
static validation is used as behavioral proof;
workflow ceremony adds latency without changing result;
new file count grows faster than demonstrated functions;
a candidate cannot be de-kernelized without losing unrelated state;
the public package and private ChatGPT kernel become coupled by copy rather than relation.
```
