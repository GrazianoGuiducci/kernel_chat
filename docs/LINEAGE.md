# Lineage and migration

`kernel_chat` is the canonical continuation of the public package developed up
to version `0.3.0` under the name Meta Semantic Kernel. The product was rebuilt
around the more precise `kernel_chat` identity, then the complete predecessor
Git ancestry and historical release were integrated here.

Its source lineage includes:

- the private ChatGPT host kernel and its present-first, turn-reactive routing;
- Meta Semantic Kernel `0.3.0`, which assembled the first portable package and
  exposed both useful relations and structural contamination;
- KA, for source-bound difference, unknowns, invalidators, reversibility, and an
  open possibility horizon;
- Meta_Skill, for situated competence, composition, metacompetence, and
  evolution;
- FDLA, produced through operator corrections when the acting system's own
  logic repeatedly narrowed the object it was trying to build;
- later MPK / SSK work, only where its causal and semantic learning had already
  changed the ChatGPT kernel and could be translated into a receiver-neutral
  relation: observation-frame continuity, semantic relation versus operational
  incarnation/effect, and correction of the first transformation that loses a
  required capability.

The MPK and SSK repositories, their product/research topology and their private
working state are not runtime dependencies of `kernel_chat`. They are part of
the source lineage of some portable relations. The public package carries the
receiver-native result, not a requirement to reproduce those systems.

The rebuild retains relations that survive removal of private paths, node state,
historical proof staging, fixed capability taxonomies, and host-specific
mechanisms. Those source projects remain their own owners.

## Deliberately not inherited

- mandatory scheduler, daemon, reducer, or agent-runtime concepts;
- a fixed behavioral-eval or competence catalogue as package identity;
- the requirement to construct artificial tests before ordinary use;
- private workspace paths, credentials, host state, or authority;
- MAIOS/MPK package topology merely because it taught a useful relation;
- SSK research vocabulary or hypotheses merely because they are newer;
- a semantic-hook runtime where the receiving host exposes none;
- a claim of support for providers without an implemented adapter.

The predecessor repository is not a second product, compatibility surface, or
runtime dependency. Its evidence remains reachable through this repository's
ancestry and the historical `v0.3.0` release; the old repository can therefore
be removed without losing the project lineage.

Future source learning follows the same rule: preserve provenance and the causal
difference that matters, then let `kernel_chat` determine its own receiving
form rather than synchronizing sibling kernels by file names or versions.
