# Portable Evolution Contract Candidate

Status: working implementation candidate
Effect authority: none by default

## Purpose

Allow the portable working incarnation to notice and preserve useful change without treating self-observation as self-approval or every correction as a kernel rewrite.

## Recognition

A material evolution signal may appear when:

```text
current representation limits the resultant
repeated routing or reentry friction remains
an unrepresented relation recurs materially
a competence composition repeatedly removes the same gap
operational continuation loses causal state
host adaptation repeatedly requires the same correction
later behavior demonstrates a reusable improvement
```

These are examples, not a trigger ceiling.

## Smallest truthful surface

A useful change may belong to:

```text
current state
active relation
operational flow/contract
host adapter
local competence
cognitive core/routing
portable invariant
external owner-native competence/project
```

Do not preselect `kernel` as the destination merely because the package contains a kernel candidate.

## Candidate movement

```text
source-linked occurrence
-> identify what changed behavior/recognition/continuation
-> consider existing owner-native/local competence or simpler representation
-> preserve candidate + counterexample/recheck when needed
-> exercise on real work
-> compare with relevant baseline
-> classify improvement / no_change / regression / tradeoff / unverified
-> integrate only at the truthful owner/surface
-> preserve recovery/supersession
```

This is a causal reading, not a mandatory procedural pipeline.

## Assimilation

Storage or successful first use is not assimilation.

Stronger evidence:

```text
candidate relation from prior occurrence
+ later relevant non-identical field
-> recognition/behavior/continuation changes materially
```

Until that later relation is observed, keep the claim bounded.

## Portability

A local improvement becomes a portability candidate only when the useful relation can be expressed without host-private paths, hidden conversational state, inherited permissions or executor identity.

A second fitting incarnation provides stronger evidence than the originating host agreeing with its own description.

## De-kernelization

Any current relation may be revised, demoted or removed when:

```text
it becomes ritual/noise
its source changes
its burden exceeds its benefit
a simpler composition preserves the useful function
counterevidence invalidates it
another host exposes that the relation was local residue
```

Preserve causal evidence and recovery; do not protect a component because of its name.

## Effect boundary

Recognizing or integrating a cognitive/package-local change does not grant authority for external effects, publication, deployment, host settings or another owner's repository.
