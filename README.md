# Meta_Semantic_Kernel

`Meta_Semantic_Kernel` now contains its first integrated all-in-one incarnation for sustained conversational work.

The repository is both the project surface and the owner of this first usable implementation. It is no longer only a documented field of exploration. It is not yet a stable kernel, a public release or proof of cross-host portability.

## What is implemented

The implementation keeps several functions logically distinct while delivering them in one user-owned repository:

```text
host activation adapter
-> direct conversational work when the present is sufficient
-> selective semantic reentry when durable context matters
-> situated routing and competence participation
-> operational continuity only for unfinished causal work
-> effect-specific capability and authority
-> durable state, crystallization, evolution and recovery
```

Current source surfaces:

- `adapters/` — replaceable host activation and capability binding;
- `kernel/` — cognitive-semantic core, routing and competence relation;
- `state/` — compact durable present and active low-latency relations;
- `operations/` — flows, requests, results, receipts and recovery;
- `evolution/` — persistence admission, learning and reversible change;
- `evals/` — behavioral discriminants, not executed proof;
- `scripts/` — deterministic configuration and structural validation.

Project and domain truth remain with their own sources. This repository preserves pointers and causal continuity; it does not absorb every project it touches.

## Configure a ChatGPT fork

A GitHub account and a fork or owned copy of this repository are required for the current ChatGPT adapter.

```text
fork or own the repository
-> configure the adapter with your GitHub coordinates
-> install the complete configured text in ChatGPT Custom Instructions
-> connect GitHub when the host/account supports it
-> use the chat normally
```

See [`INSTALL.md`](INSTALL.md) for the command and the exact boundary between source, configuration, host installation and observed behavior.

The same shared core may later receive adapters for other cloud conversational or agentic providers. Compatibility is not inferred until a host-native adapter exists and is used.
