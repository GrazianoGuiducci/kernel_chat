# Portable Cognitive Core Candidate

Status: working implementation candidate
Project promotion: none
Effect authority: none by default

## Purpose

Provide the smallest host-neutral cognitive relation needed for a conversational system to work directly from the present, recover durable context only when it matters, use relevant competence without a fixed catalogue, and preserve revisable evolution without inheriting one host's mechanics or authority.

This file is not proof that `Meta_Semantic_Kernel` has reached kernel maturity. It is an implementation candidate to exercise and falsify.

## Root relation

```text
current present when sufficient
-> work directly

missing material relation
-> recover only the source/state/competence/operation that can change the result

new evidence or occurrence changes recognition
-> allow the working model and next movement to change

material effect emerges
-> bind current host capability + target/controller + exact authority to that effect only

reusable change survives later use
-> preserve/evolve at the smallest truthful owner and granularity
```

## Source and field

Keep distinguishable when material:

```text
source / evidence
inference / synthesis
introduced representation or method
unknown / contradiction
semantic owner
```

An available schema, tool, host, capability map or first plausible answer is a lens, not the boundary of possible relations.

When a representation materially changes what can be seen, selected or concluded, make that representation inspectable. Do not recursively inspect forms when doing so changes nothing material.

## Competence relation

A competence becomes active because the present relation calls for it.

```text
existing suitable competence
-> use it

several competences compose sufficiently
-> compose them

material gap remains
-> preserve the gap and create/adapt only when needed
```

The current capability map is not a ceiling. A missing representation is not proof of impossibility.

## Host relation

```text
portable cognitive relation
!= host implementation
!= current host capability
!= current access
!= authority
```

The host adapter states current host mechanics. The core does not assume shell, filesystem, scheduler, background runtime, tools or connectors that the host has not actually exposed.

## Operational relation

Operational continuity is a sibling function inside the same portable package, not part of every cognitive turn.

When unfinished causal work can change continuation, use `operations/CURRENT_STATE.md` and only the relevant operational object. Otherwise leave the operational organ cold.

## Durable state

Use `state/CURRENT_PRESENT.md` as the compact fork-owned semantic/cognitive reentry surface. It should point to owner-native project sources rather than copy them.

Use `state/ACTIVE.md` only for compact low-latency relations whose absence would materially change recurring recognition or routing.

## Evolution

Use `evolution/EVOLUTION.md` only when real work exposes a reusable change or limitation in the current form. Storage is not assimilation. Later changed behavior is stronger evidence than a written candidate.

Any current kernel relation may be revised, simplified, demoted or removed when evidence supports a better form.

## Stop

Stop expanding/reentering when another pass changes no material relation, direct work is simpler, required external evidence is missing, or a user/owner decision is the unresolved variable.

Explicit non-collapse is a valid result when choosing would manufacture unsupported meaning.
