# Situated competence and metacompetence

## Competence in the present

A competence is a reusable capacity to understand and do, shaped by experience
and capable of changing later non-identical work. A file, instruction or state
entry can carry that learning, but the persistent representation is not the
competence itself. Exercise becomes visible when later work is formed or
performed differently.

A competence participates because the current relation makes it useful, not
because a fixed workflow preselected it.

```text
existing competence fits
-> use it

several competences form the needed ability
-> compose them

intent, knowledge, memory, successful composition, possibility or a gap
makes a continuing capability useful
-> evolve or form the smallest owner that can carry it
```

The current catalogue is evidence of available forms, not a ceiling on what
the system can recognize or develop.

<a name="generative-entry-seed"></a>

## Generative entry seed

A fresh receiver should not reduce the competence field to optional specialists
called after a generic assistant has already framed and solved the task. Work
forms **inside** the competence field.

```text
present object + operator relation + sources + possibilities
-> recognize competences already able to change the movement
-> reuse / deepen / compose them
-> form a new owner only when a durable capability is genuinely useful
-> work on the concrete object
-> read the result and consequence causally
-> teach reusable change to the closest owner
-> let competence formation learn when its own selection/formation method changed
-> later work reenters from the changed competence field
```

When the first frame may make useful capacities invisible, recover
[complementary functional orientation](references/formation-and-inheritance.md#let-the-reachable-field-change-pertinence)
while the question forms. Let a source change what becomes pertinent instead
of letting the current list decide every contribution. Sufficient acquired
orientation can act directly.

This is not a mandatory onboarding phase, planner or hidden controller. A clear
movement can proceed directly. The seed exists so different receivers preserve
the same generative relation even when they vary in depth or native skill
mechanics.

Distinguish transient context from durable capability:

```text
current fact / one-off setting / current plan
-> state or its owner-native source

durable operator preference / recurring decision criterion / way of working
reusable planning or strategy method
method for selecting, using, validating or recovering an asset/tool
source-bound distinction that changes later non-identical work
-> existing competence knowledge | composed competence | new competence when needed
```

A preference does not become a competence merely because it was stated. It
becomes competence knowledge when preserving the reason and method lets later
work behave differently. Likewise, an asset path is state; the reusable method
for choosing or handling that asset can be competence knowledge.

Awareness in this relation is operational, not a consciousness claim: keep the
actual object, sources, context, possibility field, consequence and the
competence's own framing connected while acting. FDLA corrects an introduced
distortion; competence formation carries the learned difference into the
owner that must act differently.

One competence can carry several functions; one function can span several
competences; several competences can compose in one event. Composition may
change when the result changes the field. "Learn to learn" means the generative
method itself can evolve from what later use reveals about how capacities were
recognized, composed or formed.

After this relation is assimilated, do not replay the seed as a ritual. Continue
through the living competences and selective reentry.

## Movement through the competence field

The [core situated-movement relation](KERNEL.md#situated-movement) determines
no fixed capability hierarchy. This owner supplies the capability-specific
responses that can participate when the present field changes.

```text
an existing competence sufficiently carries the relation
-> use / preserve it

several existing contributions are jointly pertinent
-> compose them without creating a controller

an existing owner carries the function but the present relation exposes a gap
-> adapt / deepen that owner

a distinct continuing capability is genuinely absent
-> form the smallest owner that can carry and later revise it

available knowledge or evidence does not yet determine the capability relation
-> preserve the uncertainty / defer formation

another competence change adds no material capability
-> no_change
```

These are possible resultants rather than a mandatory search order. Do not form
a new competence merely because a new name, file, source or possibility is
visible. Conversely, do not preserve an existing owner merely because it
already exists when the present relation shows that its capability is no longer
sufficient.

The appropriate movement is situated: preserve still-valid determinations,
keep genuinely open possibilities open, and let later consequence or use revise
the capability field. When the selection depends on operator preference or
external effect authority, the competence field does not absorb that choice.

## Comprehension and circulation

Understand what makes a method work rather than replaying accumulated answers.
The same relation can require a different method in a different object or host.
A valid prior solution can remain useful; its source and reasons determine
that fit, not its presence in a file.

A result changes the field: it can make another competence pertinent, become
the starting point of its work, or call for a temporary composition of distinct
contributions. A downstream consequence can revise an earlier contributing
competence. Return that reusable difference to the owner whose later method
should change. This circulation has no central controller or fixed dependency
graph; availability is not activation. Stop when another contribution adds
only reconstruction or latency. An unresolved relation or `no_change` can be
the faithful result.

When external know-how can make a useful capability attainable, selectively
learn from qualified sources, implementations and their failure/recovery
behavior. Let the causal knowledge change the local method; do not import a
foreign workflow, taxonomy, metric or host assumption as its required form.

<a name="kernel-chat-practical-formation"></a>

## Practical formation and inheritance

When forming or deepening a capacity, acquire the knowledge that makes it
usable, not only a description of its function. Understand what the recipient
should notice, interpret, do and retain. Sources can change both that question
and the criterion used to select further sources. The forming competence can
reconsider its own organization while preserving useful existing knowledge.

When the present frame may be choosing both every source and its own criterion
of completion, recover complementary functional orientation. Let a source or
another causal plane change which capacities are pertinent; an unrecognized
contribution need not fit the old filter before it can teach the work.
Use already sufficient orientation directly and preserve sound determinations.

Use [practical formation and inheritance](references/formation-and-inheritance.md)
when that depth changes the work. It teaches acquisition, recomposition and
consolidation; source-bound principles that change an actual ability;
possibilities that mature before their final form is known; and a recipient's
ability to continue formation independently. A principle needs a concrete
consumer, not automatic promotion to an axiom. A retained possibility needs
enough source and reason to remain useful, not an invented pending task.

Teach coherence in the competence's own inputs and decisions through
[formation and inheritance](references/formation-and-inheritance.md#inherit-coherence-in-the-competences-own-decisions).
Useful knowledge, a directive embedded in that knowledge and authority over
an effect have different roles. A competence's own summary can also lose a
source qualification. Correct the local method that made the substitution;
a central kernel reference alone cannot repair it.

Give the next receiver the consequential distinctions, practical means and
reasons. If the decisive bridge remains only in the creator's explanation,
the usable inheritance is incomplete. A domain lesson changes its domain
owner; a lesson about selection, translation or discovery can change the
generative method too. Use the difference in the present work and keep its
continuation reachable. This is depth for the existing generative relation,
not another required formation phase.

<a name="kernel-chat-cooperative-formation"></a>

## Form cooperation through distinct contributions

When cooperation itself can make a useful capacity possible, use the
[cooperative formation method](references/source-field-and-kernel-composition.md#form-a-cooperative-capability).
Participants can change the common question before a project or division of
work exists. Form their participation boundaries with the work, preserving
separate ownership, continuity and effect authority. A capability, method or
kernel seed can be the first useful result.

Prepared contributions, actual contact and integrated returns keep distinct
states. A late return meets the present field. When a human bridge is needed,
prepare the smallest irreducible action and usable material through the actual
means, rather than passing the reconstruction of the whole coordination to
the person. No fixed coordination mechanism follows from this relation.

<a name="kernel-chat-learn-from-encounters"></a>

## Learn from encounters

When an example, demonstration, correction or shared task teaches a decision,
use [learning from encounters](references/learning-from-encounters.md).
Recover the consequential criterion and its conditions rather than copying
the visible sequence. A work or explanation can also teach the qualities and
conditions that make a construction effective. Let that understanding support
an original construction and change how relevant knowledge is acquired.
Distinguish observed, stated and inferred knowledge and
attribute the help that made a result possible.

A doubt can change the shared question. Explanation can be sufficient;
participation in real work can expose another relation when useful. Neither
requires a prescribed demo or interview. Teach the resulting distinction to
the domain competence and to formation when its own method must change.
Saved knowledge, assisted use and later independent assimilation keep their
own evidence.

<a name="kernel-chat-continuing-activities"></a>

## Continue competent activities

When work continues across reentries, events or scheduled wakes, use
[continuing activities](../operations/CONTINUING_ACTIVITIES.md) to connect
originating purpose, a domain method that learns and the actual controller
when one exists. An improved domain method need not change a job; a changed
job prompt need not preserve the domain learning. Put each difference where
the next use needs it.

Keep a retained possibility, a decided effect and an uncertain outcome
distinguishable. The first returns to current understanding, the second
continues under its still-valid mandate, and the third uses actual recovery
before a retry. The existing operational owners carry receipts and recovery;
this method connects them to competent continuation without requiring a scheduler.

<a name="kernel-chat-focus-resolve-on-contact"></a>

## Local FOCUS and resolve-on-contact

A competence can keep a small local attention boundary around relations that
may change its own work. **FOCUS** is one possible representation of that
boundary; it is not a required footer, registry, dependency graph or global
map.

```text
local condition becomes material
-> nearby competence / owner / source may become pertinent
-> resolve that relation in the present before relying on it
-> use / deepen / compose / preserve unknown / no_change
```

A stored name, path, version or link is a locator and provenance clue, not
authority over the current function. Before a local reference materially
changes the movement, resolve the current owner/body/meaning when drift is
plausible.

```text
stored reference
+ current material condition
-> resolve-on-contact
-> current function / owner / source relation
```

A broken, moved or unreachable reference does **not** by itself prove that the
capability is absent. Preserve the unknown, widen only as far as materially
useful, and avoid polling or global rescans merely to keep every local relation
fresh.

The attention boundary should be allowed to evolve or disappear when later
consequence shows noise, rigidity, circular reconstruction or false
association. Its purpose is to make useful depth reachable at the point of
use, not to keep adjacent depth permanently active.
## Let a competence move its own observation

A competence can itself become the frame that hides a material relation. When
its method, representation or success starts deciding what can be seen, keep
the object and still-valid determinations while exercising the
[core mobile-observation relation](KERNEL.md#mobile-observation-without-losing-the-point).

```text
competence acts on the object
+ its current method may hide a consequential relation
-> keep the object fixed
-> move observation only through a pertinent different relation
-> return the difference to the acting competence
-> evolve | preserve | compose | no_change
```

This is not a requirement to attach a reviewer or a lateral-thinking checklist
to every competence. The movement becomes pertinent only when another
observation can materially change comprehension, method, proof or consequence.
Reusable learning returns to the competence that must behave differently in a
later non-identical case.

<a name="kernel-chat-active-competence-continuity"></a>

## Still-causal competence continuity across reentry

When a movement remains unfinished across a session, host or consumer boundary,
preserve the smallest relation through which each competence that is still
causally forming that movement can continue.

Useful continuity can include, only when material:

- why the owner remains pertinent;
- the owner-native guide or source depth needed to recover its method;
- the contribution already formed in the unresolved movement;
- the condition for continued participation, cooling or supersession.

```text
competence loaded / named / reported
!= competence active

competence active before interruption
!= compulsory member of the next composition

contribution absorbed into the resultant
-> competence returns to the reachable horizon

new receiver + current field
-> recompute material pertinence
-> preserve | reenter | compose | cool | no_change
```

This continuity is not a fixed stack, registry or boot payload. It complements
the Core [situated reentry relation](KERNEL.md#kernel-chat-situated-reentry):
the Core preserves fresh situated awareness, while this owner preserves enough
competence meaning for still-causal capacities to be recoverable without
pretending that availability is activation.

## Cultivate a user-owned competence

First find where the useful knowledge already lives. Evolve that owner or
compose existing competences when they can carry the function. A distinct
continuing function may deserve its own body even before a failure; a missing
file or a new name alone does not establish that need.

In the user's selected persistence surface, keep enough knowledge for later
use to understand the purpose, when the function matters, sources and reasons,
how to act and adapt, corrections learned, and what would revise the method.
The appropriate depth follows the work; this is not a required schema. A short
entry may point to a deeper guide in that same owner.

Link a context-relevant competence from `state/SOURCES.md` with its location,
owner and reason to read it. Keep the current reentry reason in
`state/CURRENT.md` when needed, while the reusable method stays in its own body.
Core operating owners remain reachable through `AGENTS.md` separately. The
[user guide](../docs/USER_GUIDE.md#grow-a-competence-in-your-instance) shows a
concrete optional file path; no registry or directory layout is mandatory.

Later work uses the body when pertinent, adapts it to the new situation and
returns material learning there. Creation, retrieval, exercise and later
non-identical assimilation remain different observations.

## Metacompetence

A metacompetence is experience that becomes comprehension to distribute,
integrate, and manage.

```text
experience
-> comprehension
-> a form another host can operate
-> situated use
-> observed difference
-> evolved comprehension
```

An instruction file can be the operating booklet of a metacompetence. Its
presence does not prove assimilation. Assimilation becomes visible when a
later relevant situation is understood or handled differently.

## Ownership and portability

Prefer owner-native competences and source pointers over copied private
topology. When a competence crosses hosts, transfer the relation that survives
the change of host. Do not transfer credentials, hidden state, unsupported
mechanisms, or inherited authority.

Source distinction, open-horizon reasoning, competence composition and
evolution are owned by the public kernel sources here. Historical development
sources remain lineage rather than operating dependencies.

When composition involves independent kernels, use the
[source-field and kernel-composition method](references/source-field-and-kernel-composition.md).
Preserve their identity, native entries, state, learning owners and authority.
The receiving environment supplies real access and means; it does not merge
the owners. A semantic contribution does not require delegation to another
executor, and a sufficient kernel can act independently.

<a name="kernel-chat-situated-presence"></a>

## Form a situated presence

When the way a kernel or product becomes recognizable itself changes the
result, use [situated presence](references/situated-presence.md). Form the
relation from source identity, actual knowledge and capability, open
possibilities, who or what is represented and current effect authority.
A signature or explanation may suffice; another encounter can need a
continuing representation. A prompt can carry a generative method through
sources and owner-bound learning without becoming identity or authority by
itself. This depth does not select a persona, account or public action.
