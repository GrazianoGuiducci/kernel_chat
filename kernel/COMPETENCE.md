# Portable Situated Competence Relation Candidate

Status: working implementation candidate

## Purpose

Let useful competence participate in the present without copying a global competence architecture or turning the known catalogue into a ceiling.

Meta_Skill remains the canonical owner of competence/metacompetence architecture in the source ecosystem. This portable file carries only the host-facing relation required by the working incarnation.

## Relation

```text
present need or friction
-> does an available owner-native/local competence fit?
   yes -> use it
-> can existing competences compose coherently?
   yes -> compose them
-> does a material gap remain?
   yes -> preserve a source-bound candidate or retained unknown
-> exercise on real work
-> compare resulting behavior/recognition
-> maintain / revise / reject / cool / route to real owner
```

This is not a mandatory sequence. Direct work may need no explicit competence resolution.

## Availability is not activation

Keep distinguishable:

```text
represented
available on this host
relevant now
active in this movement
verified by use
assimilated in later behavior
authorized for an effect
```

One state does not imply the next.

## Open relation

A material relation absent from the current competence map may remain:

```text
unrepresented
retained_unknown
candidate
```

rather than being discarded, forced into the nearest family or declared impossible.

## Local extension

Create/adapt a package-local competence only when a material gap remains after reuse/composition and when the local form has a falsifiable expected behavior.

A local candidate should preserve only what is needed to answer:

```text
what need/gap appeared?
what source/evidence supports it?
what existing competence/composition was considered?
what behavior should change?
what would invalidate it?
what owner should receive a reusable invariant if it generalizes?
```

No fixed artifact schema is required until implementation or exchange needs one.

## Assimilation

A competence is not assimilated because it is documented or successfully used once.

Stronger evidence is:

```text
prior occurrence/candidate
+ later relevant but non-identical field
-> materially different recognition or behavior
```

Until then, classify it as evidence/candidate rather than durable competence where that distinction matters.

## Effect boundary

Competence relevance does not grant authority. If an activated competence proposes an external or repository effect, resolve that effect separately when it becomes concrete.
